# 4라운드 E2E 브라우저 점검 결과

환경: Chromium(playwright-core, 헤드리스) + wsgiref(127.0.0.1:18940), DB 는 agent-r4-e2e/data/e2e.db, 가짜 sendfax/faxstat/faxrm/faxalter 를 PATH 앞에 두고 로컬 가짜 SMTP(18951)와 닫힌 포트(18952)만 사용. 스크린샷은 agent-r4-e2e/shots/ (114장). 시나리오 스크립트는 agent-r4-e2e/s1.js ~ s13.js. 저장소 소스는 수정하지 않았음.

## 새로 발견한 결함

### R4E-01 [중간] 아카이브 검색이 일치 결과가 없으면 조작된 결과를 만들어 냄
- 재현: admin 로그인, /archive?search=zzzznomatch (또는 faxid=99999, search=alpha 등 실제 DB 의 보관 팩스 설명과 무관한 모든 키워드/ID) 로 검색.
- 결과: "회사=검색어, +1-555-0199, Quarterly Financial Fax Transmission <검색어>, 2쪽, 2026-09-29 09:30" 결과 1건이 표시됨. 실제 보관 팩스(fid 13~32, 20건, inbox=0)는 어떤 조건으로도 나타나지 않고, 날짜/카테고리/송수신 필터만 쓰면 0건. 사용자는 "검색에 성공했다"고 믿게 되며, 결과의 View/PDF 는 존재하지 않는 팩스를 가리킴. 없는 fid 로 PDF 를 열면 가짜 PDF 가 내려옴(F4-12).
- 원인 코드: views/archive.py 의 `if not results:` 골든 마스터용 폴백. USR-01, F1-10, R3B-09 와 관련되나 "검색어 에코 가짜 행"은 별도 문제.
- 스크린샷: shots/s7-fake-result.png, shots/s7-archive.png
- 확인 수준: 재현(브라우저, 20건 시드 DB 로 확인)

### R4E-02 [낮음] SMTP 진단 테스트를 누르면 폼이 입력한 호스트/포트를 잃고 기본값으로 재렌더됨
- 재현: /admin/smtp 에서 호스트 127.0.0.1, 포트 18951, 수신 주소 입력 후 "test" 클릭.
- 결과: 진단 결과 패널은 입력값으로 정상 실행(가짜 SMTP 서버에 EHLO/MAIL/RCPT/DATA 도달)되나 재렌더된 폼은 localhost/25 로 돌아가, 사용자가 같은 값으로 "저장"을 누르려면 다시 입력해야 함(저장 자체도 K01 로 반영 안 됨). 닫힌 포트 테스트 후에도 동일.
- 스크린샷: shots/s9-smtp-test-ok.png, shots/s9-smtp-test.png
- 확인 수준: 재현(브라우저)

### R4E-03 [낮음] 태블릿 폭(768px)에서 공통 헤더가 넘쳐 가로 스크롤이 생기고 수신함 표의 작업 열이 잘림
- 재현: 뷰포트 768x1024 로 로그인 후 /login, /inbox, /sendfax, /archive, /addressbook, /settings, /viewfax 방문.
- 결과: documentElement.scrollWidth 832(또는 807) > 768. 헤더 오른쪽 사용자 영역(Settings, Logout)이 화면 밖으로 밀리고, 수신함 표의 ACTIONS 열(View/PDF/Reply)이 잘려 보임. 로그인 화면도 832px. /admin 계열은 정상, 390px 은 주소록만 넘침(R3H-12).
- 스크린샷: shots/s11-tablet-_inbox.png, s11-tablet-_login.png, s11-tablet-_viewfax_fid_11.png
- 확인 수준: 재현(브라우저, scrollWidth 측정과 스크린샷)

### R4E-04 [중간] 설정에서 저장한 표시 언어가 계정이 아니라 브라우저 쿠키에만 남음
- 재현: /settings 에서 언어를 ja 로 저장 후 DB 조회, 다른 브라우저 컨텍스트에서 같은 계정으로 로그인.
- 결과: Set-Cookie _LOCALE_=ja(만료 약 1년)만 생기고 UserAccount.language 는 'en' 그대로. 다른 브라우저/기기로 로그인하면 영어로 돌아가고, 화면은 "저장됨"이라고 표시. F4-22(DB 값이 화면에 적용되지 않음)의 반대 방향(저장이 DB 로 가지 않음)이며 UI-01 은 이름/비밀번호 위주라 언어 항목은 별도.
- 스크린샷: 없음(쿠키/DB 출력으로 확인)
- 확인 수준: 재현(브라우저 쿠키 목록과 DB 쿼리)

### R4E-05 [낮음] 로그인 화면의 SAML 버튼이 미설정 상태에서도 노출되고 누르면 안내 없이 /login 으로 되돌아옴
- 재현: 로그인 화면에서 "SAML 2.0 Enterprise SSO" 클릭(관리자 SAML 설정 없음).
- 결과: /auth/saml/login 이 302 로 /login 으로 보내고 오류/안내 문구 없음. R3H-20 은 "항상 보이는 SSO/패스키 버튼"을 다루지만, 클릭 후 무안내 리다이렉트의 사용자 영향(버튼이 고장난 것처럼 보임)은 별도 확인 항목.
- 스크린샷: shots/s10-saml-login.png
- 확인 수준: 재현(브라우저)
